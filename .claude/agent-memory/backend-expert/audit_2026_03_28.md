Audit date: 2026-03-28. 14 findings, ordered P1 → P3.

**Why:** First full audit of the Tripplet backend. Not all findings have been fixed.
**How to apply:** Use as a living checklist. Strike findings when resolved. Add new ones here rather than losing them across sessions.

## P1 — Security / Data Correctness

1. Middleware does NOT verify the JWT — only checks cookie presence. An expired or forged token passes the guard. Fix: call verifyToken() in middleware and redirect on failure.
2. /api/code/route.ts has NO rate limiter. It fans out potentially 5+ sequential upstream AI calls (callProviderChat x N files). A single authed user can exhaust the inference backend quota. Fix: add a dedicated codeLimiter.
3. imageBase64 payload in /api/imagine and /api/imagine-video has no size cap. A client can send a 100MB string through the JSON body, OOMing the Node process. Fix: validate length (e.g., ≤ 2MB base64 ≈ 1.5MB image).
4. /api/chat/history/route.ts fetches ALL messages for ALL conversations in a single JOIN with no LIMIT or pagination. For a user with hundreds of chats this query returns megabytes, is slow, and can OOM the serverless function. Fix: paginate conversations (e.g., last 30) and lazy-load messages per conversation.
5. Guest message cap (chat/route.ts:194) counts user messages from the client-supplied array — a malicious client that simply sends fewer messages than they actually have will bypass the server-side cap. The cap is advisory, not enforcement. Fix is non-trivial (requires server-side session state for guests); document the limitation clearly.

## P2 — Reliability / Correctness

6. streamChat (chat-client.ts) has no reader.cancel() / reader.releaseLock() in its cleanup path. If the generator is abandoned (client disconnects) the ReadableStreamDefaultReader holds the connection open until the 120s AbortSignal fires. Fix: wrap the while(true) body in try/finally and call reader.cancel().
7. storeMemory fires inside the ReadableStream start() callback after the stream is done, but controller.close() has already been called before the .catch() path runs. If the stream errored, fullResponse may be partial. The bigger issue: a fire-and-forget inside a streaming handler can throw after the response is gone and silently lose data. Fix: move post-stream database writes outside the ReadableStream constructor using a TransformStream or a post-response hook.
8. /api/code/route.ts generates N files sequentially inside a for-of loop (lines 405-427), each waiting on callProviderChat with a 60s timeout. With 10 files that is up to 600 seconds — well beyond any serverless timeout. Fix: run file generations in bounded parallel batches (e.g., Promise.all with concurrency limit of 3).
9. VideoService.generate() fires count Promise.all submissions in parallel (up to 5). If the inference backend rate-limits any of them, the whole batch fails with no retry. Fix: add a small delay between submissions or catch per-promise errors and return partial results.
10. callProviderChat for openai and claude providers (code/route.ts) has NO AbortSignal.timeout(). Only the internal path has a 60s timeout. A hung OpenAI or Anthropic call will block the handler indefinitely. Fix: add signal: AbortSignal.timeout(60_000) to both fetch calls.

## P3 — Performance / Minor

11. system-prompt.ts loadPromptFile() uses fs.existsSync + fs.readFileSync on every cache miss. In production (Vercel) the filesystem is read-only and stable — the 60s TTL is fine, but existsSync adds a syscall on every cold cache hit. Minor: consider bundling sprompts at build time or increasing TTL to 5 min in production.
12. /api/chat/title/route.ts: the title route is listed in PUBLIC_API_ROUTES in middleware.ts (no auth required at the edge), AND it has its own titleLimiter, but unauthenticated callers get rate-limited by IP only. Anyone can probe conversation titles for free (cheap model, but still costs tokens). Consider requiring auth for the title endpoint.
13. LRU rate limiter is in-process (single server instance). On Vercel with multiple serverless instances each instance has its own counter, so the real per-user rate is LIMITS.chat * (number of instances). For production scale, replace with an atomic Redis/Vercel KV counter.
14. supabase client in src/lib/db/supabase.ts throws at module load time if env vars are missing. This kills all API routes cold, not just the ones that use it. Fine for production, but makes local development painful. Consider lazy initialization or a startup health check.

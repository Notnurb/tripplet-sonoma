## Executive summary

The codebase is in noticeably better shape than the historical audit docs describe. The 2026 hardcoded-secrets-and-SQL-injection incident referenced in `docs/security/CRITICAL_SECURITY_AUDIT.md` and `SECURITY_TASKS.md` is **resolved** — no hardcoded secrets found in a fresh grep pass, `npm audit --omit=dev --audit-level=high` reports zero vulnerabilities, and the security-sensitive fetch/exec paths (SSRF guard, worker-isolated Python, array-form `spawn()`) are implemented as documented. Auth is a single coherent JWT system with the Better Auth remnants clearly quarantined in both code comments and the Prisma schema.

The main open item is a genuinely incomplete feature (password-reset emails never send) rather than a security hole, plus normal end-of-cycle housekeeping: an ISC→MIT license mismatch just fixed in this pass, several "experimental" route groups that are undocumented beyond a one-line dismissal, and the large legacy `docs/audits/review.txt` file that should probably be pruned or archived now that its findings are largely stale/superseded.

## Findings

### High

1. **Password reset never actually emails the user.** `src/app/api/auth/forgot-password/route.ts:44` — `// TODO: Send reset email via email service (e.g. Resend, SendGrid)`. The route presumably generates a `PasswordResetToken` row but there's no way for the user to receive it, so the forgot-password flow is dead-ended in production today. Recommendation: either wire up an email provider or, if this is intentionally unfinished, surface that clearly in the UI (don't show a "check your email" success state if no email is sent) and in `docs/wiki/Contributing-FAQ.md` / `SECURITY.md` so it isn't mistaken for a working control.

### Medium

2. **`ADMIN_USER_IDS` is the only gate on `/api/looptrain/start`, a route that spawns `python3` server-side.** (`src/app/api/looptrain/start/route.ts:7,15`) The allowlist is a comma-separated env var compared with plain `.includes()`. This is fine as a mechanism, but there's no logging/alerting around who triggers a spawn, and no rate limit distinct from the general per-IP limiter — a compromised admin account (or an admin id that leaks, e.g. via logs) has unrestrained process-spawn access. Recommendation: add an audit log line on every successful spawn (who, when, args) and confirm `ADMIN_USER_IDS` is never empty-string-matched (an empty allowlist entry from a trailing comma in the env var would need to not match `''` userId, which cannot happen since `auth()` requires a real cuid — low risk, but worth a unit test given how cheap one would be).

3. **`docs/audits/review.txt` (3,382 lines) is stale and risks being trusted as current.** It predates recent fixes (real Python via Pyodide, the Better Auth removal, rate-limit KV backing) documented in `CHANGELOG.md`. Anyone opening it without cross-checking dates will draw wrong conclusions about what's still broken. Recommendation: either delete it now that its actionable items are captured in `SECURITY.md`/`CHANGELOG.md`, or prepend a large "SUPERSEDED — see CHANGELOG.md and this file's own dated addenda" banner at the top.

4. **Experimental route surface (`/arena`, `/hivemind`, `/pixel`, `/spark`, `/studio`, `/skins`, `/generate`, `/tgrablockbatch`, `/trippletgrabthing`, `/v1/chat`, `/v2/chat`) has no auth/rate-limit audit trail in this review** — `CLAUDE.md` explicitly says "treat as prototypes," which this review respects by not deep-diving them, but that also means nobody currently knows if any of them are internet-reachable with no auth check at all. Recommendation: a lightweight follow-up pass just confirming each either requires auth or is intentionally public, so "prototype" doesn't silently become "unaudited attack surface."

### Low

5. **`package.json` license field was `ISC` while the actual `LICENSE` file (newly added this session) is MIT** — now corrected as part of this task's license work, but flagging so it's understood as resolved rather than newly discovered. No action needed.

6. **`User.emailVerified` is typed `Boolean` with a comment explaining it exists only because Better Auth's (now-removed) email-verification flow wrote to it.** (`prisma/schema.prisma:18-20`) Nothing sets it anymore since Better Auth is gone — it's a permanently-`false` dead field for any user created going forward. Low priority, but worth a note in `docs/wiki/Database.md` (added) so a future migration doesn't "helpfully" repurpose it without realizing the history.

7. **`docs/security/SECURITY_TASKS.md` reads as an in-progress task list assigned to "Agent 3"** rather than a durable doc — it's useful as history but shouldn't be confused with current security posture (`SECURITY.md` is the current source of truth). Recommendation: move it under `docs/audits/` alongside `review.txt` and `CRITICAL_SECURITY_AUDIT.md` so `docs/security/` only contains live, current-state docs.

### Notes (no action needed, verified fine)

- `npm audit --omit=dev --audit-level=high`: **0 vulnerabilities** at time of review.
- No hardcoded secrets found in a fresh grep across `src/`, `services/`, `scripts/` for common key/token/password literal patterns.
- Both server-side `child_process.spawn()` call sites (`src/app/api/cloud-env/command/route.ts`, `src/app/api/looptrain/start/route.ts`) use array-form arguments, not shell string interpolation — no shell-injection vector from the spawn mechanism itself. `cloud-env`'s workspace slug is regex-validated (`^[a-z0-9-]{1,64}$`) before path construction, blocking path traversal via slug.
- SSRF guard, Python worker-thread isolation, and the injection sanitizer described in `SECURITY.md`/`docs/ARCHITECTURE.md` all correspond to real code (`src/lib/ai/websearch.ts`, `src/lib/python/run.ts`, `src/lib/security/sanitize.ts`) — docs are not aspirational here.
- Auth degrade-to-guest behavior in `src/lib/auth/session.ts` is consistently respected by the two process-spawning routes reviewed (`cloud-env`, `looptrain`) — both explicitly check for a real `userId` rather than assuming `auth()` throwing means "no access."
- CI (`.github/workflows/ci.yml`) genuinely gates type-check + lint + unit tests + prod-tree audit, matching what `CONTRIBUTING.md` asks contributors to run locally.
